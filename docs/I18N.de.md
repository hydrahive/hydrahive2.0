# Internationalisierung der HydraHive-Dokumentation

> 🇬🇧 [English version](I18N.md)

Die HydraHive-Produktdokumentation wird in zwei Sprachen veröffentlicht:

| Code | Sprache | Zielgruppe |
|------|---------|-----------|
| `*.md` (Standard) | Englisch | Internationale Mitwirkende, Reviewer, künftige Team-Mitglieder |
| `*.de.md` | Deutsch | Hauptsprache der Nutzer/Admins, kundenorientierte Hand-Übergabe |

## Regeln

1. **Englisch bleibt die kanonische Quelle.** Jede `*.md`-Datei in diesem Repository ist die maßgebliche Fassung. Die `.de.md`-Datei ist eine übersetzte Spiegelung.
2. **Ein Spiegel pro Datei.** Die übersetzte Kopie liegt direkt neben dem englischen Original und nutzt denselben Pfad, nur mit dem `.de`-Einschub vor dem `.md`-Suffix.
   - `README.md` → `README.de.md`
   - `docs/ARCHITECTURE.md` → `docs/ARCHITECTURE.de.md`
3. **Sichtbarer Sprachzeiger oben.** Jede Datei beginnt mit genau einer Zeile, die auf die andere Sprache verlinkt. Verwende den echten Dateinamen im Link, zum Beispiel `> 🇩🇪 Deutsche Version → README.de.md` oder `> 🇬🇧 English version → README.md`; keinen wörtlichen Platzhalter verwenden.
4. **Gleiche Struktur, gleiche Anker.** Die deutsche Spiegelung behält Überschriften, Linkziele und Codeblock-Sprachen identisch zum englischen Original. Eine umbenannte Überschrift im Englischen erfordert dieselbe Umbenennung im Deutschen und umgekehrt.
5. **Keine gemischte Sprache in einer Datei.** Entweder vollständig übersetzt oder gar kein Spiegel (dann nur Verweis auf die englische Version).
6. **Codeblöcke, Pfade, Identifier und Konfigurationsschlüssel werden nie übersetzt.** Tabellen mit Umgebungsvariablen, Modul-IDs, API-Pfaden, CLI-Flags und Ähnlichem bleiben englisch.
7. **Änderungen wandern gemeinsam.** Wird das englische Original editiert, muss die deutsche Spiegelung im selben Commit (oder einem Folge-Commit mit Verweis auf die Original-Änderung) angepasst werden. Veraltete Spiegelungen werden im selben PR reviewt.
